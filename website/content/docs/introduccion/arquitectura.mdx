responsabilidad clara y puede usarse por separado.

## Las capas

### Modelos y contratos

`cpeforge-core` define los modelos de todos los comprobantes, el importe en
letras y los contratos (`ports`) que implementan los demás crates. No sabe nada
de XML, firma ni red: es la base que todos comparten.

### Emisión

| Crate | Responsabilidad |
| --- | --- |
| `cpeforge-xml` | Convierte un modelo en XML UBL 2.0/2.1 sin firmar |
| `cpeforge-xmldsig` | Firma y verifica (XMLDSig, C14N, X.509) con el perfil de SUNAT |
| `cpeforge-ws` | Empaqueta en ZIP, llama a los servicios SOAP, lee el CDR y clasifica con `TaxStatus` |
| `cpeforge-gre-api` | Cliente HTTP de bajo nivel de la API REST de guías de remisión |
| `cpeforge` | Fachadas `See` y `Api` que encadenan todo lo anterior |

### Después de emitir

| Crate | Responsabilidad |
| --- | --- |
| `cpeforge-report` | Representación impresa en HTML, con QR |
| `cpeforge-xml-parser` | Lee un XML de comprobante y lo convierte en modelos |
| `cpeforge-xcodes` | Catálogo de los 2 077 códigos de retorno de SUNAT |

### Validación

| Crate | Responsabilidad |
| --- | --- |
| `cpeforge-validator` | Reglas sobre los modelos, antes de generar el XML |
| `cpeforge-ubl-validator` | Validación contra los esquemas XSD de UBL (libxml2) |
| `cpeforge-cpe-validator` | Reglas XSL de SUNAT (libxslt) |

### Apoyo

`cpeforge-xml-limits` comprueba límites sobre el texto del XML (anidamiento,
atributos, DTD) **antes** de construir el árbol. Lo usan los crates que leen XML
externo para no caer ante entradas hostiles.

## Principios de diseño

- **Lógica pura separada de la E/S.** El transporte HTTP y el reloj se inyectan:
  las pruebas usan dobles sin red y fechas fijas.
- **Sin `panic!` ante entradas externas.** Ningún `unwrap()` ni `expect()`; los
  errores son tipos con contexto.
- **Sin criptografía propia.** La firma usa OpenSSL a través del crate
  `openssl`.
- **Dependencias internas fuera de la API pública.** Ningún tipo de `openssl`,
  `roxmltree`, `reqwest` o `zip` aparece en la API; solo `jiff` y
  `rust_decimal`, que son las fechas y los importes de los modelos.
